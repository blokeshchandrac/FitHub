# FitHub final schedule changes

The original Waterfall plan placed requirements, architecture and Must Have implementation before selected Should/Could work. That sequence was retained, but the completion window extended beyond the Phase 2 baseline because concrete manual testing exposed integration gaps that were not visible from compiled screens alone.

The largest extension occurred during Phase 3. Registration consent and workout rest time were completed on 21 October. Connected equipment clearance, secure password reset, notification preferences, CI hardening and cloud-deployment preparation followed on 22 October. Render, Neon, Brevo and Stripe Test Mode deployment verification ran from 22 to 24 October. Final hosted acceptance on 24-25 October found and corrected fault-comment validation, PostgreSQL retry boundaries for payment/class booking/password reset, class-capacity behaviour and Active Member equipment-hub access.

The final Gantt distinguishes the planned baseline from the evidence-backed actual timeline. Dates come from the original plans, Git commit timestamps, Phase 2 submission/evidence dates, deployment evidence and final acceptance records. No unsupported precision is added for activities without dated evidence.
